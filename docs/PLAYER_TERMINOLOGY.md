# Player-facing terminology guide

This guide keeps Rainbow Six Siege's recognizable vocabulary while making the app understandable to casual and first-time players. UI wording should describe the actual action and reward; do not change game mechanics as part of copy edits.

## Writing rules
- Prefer short, action-led Persian labels in buttons.
- Keep official operator names, map names, weapon names, and established terms where replacing them would make the app less accurate.
- Explain uncommon terms on first use or with a short tooltip.
- Use one Persian term consistently across navigation, cards, confirmations, and toasts.
- Do not imply that the app awards in-game Siege XP or official Ubisoft rewards. The XP and Alpha Pack references here describe this app's own progression/reward simulator.
- Keep IDs, element IDs, function names, data keys, and event handlers unchanged when editing copy.

## UX copy checks
- Buttons should state the action: “انتخاب اپراتور تصادفی”, “پیشنهاد ترکیب دو اپراتور”, “ثبت چالش و دریافت امتیاز”.
- Confirmation messages should state what was recorded and whether points were awarded.
- When a daily app XP limit is reached, say “سهمیه‌ی روزانه‌ی امتیاز تجربه در این بخش تمام شده”.
- Timer states should use “آماده”، “در حال اجرا”، “متوقف” and “پایان زمان”.
- Explain that excluded operators are omitted from this app's random selection, not banned from the actual game.
- Keep descriptions short enough for mobile; use a tooltip/title for secondary context instead of adding paragraphs to every card.
